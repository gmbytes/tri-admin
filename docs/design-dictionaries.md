# 字典与明细

Task 6 按已批准的全新实现计划细化。本模块采用独立 `dictionaries` / `dictionary_items` 集合，避免明细数组随使用增长；所有列表有界分页，默认按创建时间或显式 `sort` 与 ID 稳定排序。

- `/api/v1/dictionaries`：分页查询、新增；`/{id}`：读取、版本化修改、软删除。
- `/{id}/items`：明细分页查询、新增；`/{id}/items/{itemId}`：版本化修改、软删除。
- 字典字段：name、key、description、enabled。key 为 1–64 位小写字母开头的字母、数字、点、短横线或下划线；活动字典中唯一。
- 明细字段：label、value、sort、enabled。value 为非空字符串，同字典的活动明细中唯一；不同字典可复用。enabled 是配置内容的状态，不影响有权限管理员读取维护。
- 字典与明细均提供字符串 ID、版本、RFC3339 时间。PATCH 省略字段保持原值，显式 null 拒绝；描述可用空字符串清空。字段白名单和长度限制在服务端执行。
- `dictionaries.read/write` 分别控制全部读取和全部修改，配置类字典不采用业务记录的自身/角色数据范围。
- 删除字典前必须清空活动明细；不隐式级联删除。父文档是同一字典内写操作的事务锁，创建/编辑/删除明细与父删除互斥，避免并发产生孤立活动明细。修改明细不改变字典的业务版本。
- 所有修改与审计事件同一事务提交；唯一索引处理并发重名，版本冲突返回 409。schema 为独立版本记录，就绪检查要求其已迁移。
- 页面采用字典列表与明细抽屉，保留独立搜索/分页/编辑状态；写按钮按权限显示，错误和旧版本不静默覆盖。

验收覆盖真实 MongoDB 的 CRUD、空值/未知字段、字面前缀搜索、分页排序、唯一性、软删除、越权、并发版本与父子删除竞争，以及真实后端页面的创建、编辑和删除流程。
