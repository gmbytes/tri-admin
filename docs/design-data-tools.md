# 数据工具实施细化

本设计落实 V3 Task 7 的新资源 CSV/XLSX 能力，完整范围仍含模板、字段映射、受控筛选、预览、逐行结果、可重放批次、导出和页面。当前已接入参数、字典/明细导入导出，以及按范围过滤的用户资料导出；其他能力按以下剩余范围继续实施，不能将阶段完成等同 Task 7 完成。

实现选择：采用服务端解析 CSV/XLSX，复用新参数验证和事务写入规则。相较客户端直接循环调用创建接口，这可以把每行的数据创建、审计和导入回执放在同一 MongoDB 事务里，处理丢失响应和重试。相较通用数据库导入，不接受集合、SQL、表达式或任意投影。

边界：文件最多 6 MiB、2000 数据行、32 列，单元格最多 16 KiB，转换结果最多 8 MiB。XLSX 仅一个工作表，ZIP 项目和总展开体积受限，先检查工作表坐标和公式再交给读取库，拒绝宏、外链、公式、日期及错误单元格。数字遵循桌面安全范围。XLSX 文本显式写为字符串；CSV 公式危险前缀加单引号（该保护字符在 CSV 再导入时保留，XLSX 可无损往返）。

资源注册明确列出读取/写入权限和字段。参数导入只创建，不覆盖现有 key；valueType 决定 value 的字符串/数字/布尔/JSON 解析并复用参数校验。用户资料仅导出 id、username、displayName、status、version；用户范围过滤在查询和限制前执行，禁止密码、Token、角色权限或密钥列。用户导入及其他资源接入仍须专门实现对应不变量。

预览以操作者和 UUID 请求标识绑定文件摘要、格式及映射；重复标识携带不同输入返回冲突。记录逐行标准化字段及验证/重复错误，24 小时后禁止首次应用。应用每批最多 100 个行号，每行一个事务，创建参数、创建审计、保存结果原子提交。失败、应用结果和原始输入保留供查询；重放已应用行只返回原回执。其他操作者得到 404；每次预览、查询、应用、导出均检查当前权限。预览不是授权承诺，应用时重新检查唯一性。

按操作者限制最多 32 项未到期且有待处理行的预览；重复同一请求和终态记录不占新名额。历史按资源、状态分页，内容到期后保留轻量回执，避免大预览永久保存或未完成任务被最近记录遮住。应用事务采用有界行投影，并有实际大批次性能证据。

字典资源扩展：字典字段为 name/key/description/enabled；明细字段为 dictionaryKey/label/value/sort/enabled。明细的 dictionaryKey 在预览事务内绑定实际父级 ObjectId，应用时同时核对父级 ID 和标识，再复用普通明细创建的父级写入栅栏。父级改名、删除或同标识被新父级占用均报告该行冲突，不能转投新父级。明细唯一性按父级和值判断，导出通过活动父级关联，只输出活动明细。每种资源声明独立读取/写入权限，历史查询先按可读资源过滤。自身 schema v1→v2 为原行补齐内部 parentId:null；这是新工程自身模型升级，不提供旧系统适配。

批次应用改为每行只投影对应的单个行及必要元数据，避免每应用一行就读取整份预览。批次起止仍返回完整结果，保持相同的原子提交和查询恢复协议。

范围核对：原工程具备命名模板的保存、编辑、复制、删除与大批量异步导出。后续采用新资源字段注册、受控筛选、模板版本和持久任务实现对应能力；当前空模板下载和 2000 行同步导出属于第一阶段。模板不能包含原始数据库表名、SQL、连接或任意表达式；导出任务使用授权文件资源并记录可查询结果。完成这些能力、友好字段映射与历史/内容保留策略后，再审计整个数据工具交付范围。

页面会展示资源、格式、字段映射、筛选、模板下载、预览逐行错误、批次应用进度及可查询的导入标识。内容只进入本地选取文件、请求和私有预览数据，不进入日志或 WebStorage；本地恢复仅存服务地址/操作者范围内的导入标识。

字段映射使用单独的只读文件检查：在相同大小/类型限制及计算名额下解析所选内容，只返回资源、格式、原始字节 SHA-256、表头和行数，不建立导入记录、不返回行值。客户端核对摘要和来源后，以资源字段到来源列的下拉选择器呈现；同名列自动匹配，必填/未知/重复来源检查在预览前完成，最终仍由服务器重新解析和验证。导入格式由所选文件确定，导出格式独立设置；读取表头失败可在内存中重试，取消和离开页面关闭源句柄并丢弃迟到结果。

历史与保留策略：自身 schema v3 记录总行、待处理、已创建、错误和过期计数。32 项限制只计仍未到期且存在待处理行的预览；原回执重放不占新名额。按当前资源读取权限过滤后分页，支持资源和待处理/完成/部分完成/错误/过期状态筛选。应用每行时，业务数据、审计、回执和计数在同一事务更新。

原始行内容保留至创建后 24 小时；公开接口到期后立即不返回行值及原始标识，明确显示 expired（等待清理），后台清理成功后显示 redacted。每次启动和约 10 秒周期最多处理 100 项到期预览，逐项事务清除原行值、原标识与父级绑定，保留请求指纹、行号、状态、错误码、目标 ID 及汇总，并写入系统清理审计。未提交行转为 expired；已创建行回执保留，重试不能重新创建或复活已删除目标。清理失败回滚并由下轮重试，不删除未到期内容，不触碰业务资源。

实施顺序：格式边界 RED→GREEN；事务化参数写入及持久回执 RED→GREEN；受控导出与范围测试；页面及真实 CSV/XLSX 流程；全量适当回归。使用 csv 1.4.0、calamine 0.37.0、rust_xlsxwriter 0.101.0，官方元数据最低 Rust 分别为 1.73、1.88、1.88，均满足项目 1.94。
