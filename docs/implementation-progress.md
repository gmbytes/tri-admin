## Task 3 验证与裁定

- 新接口 `/api/v1/auth/login`、`refresh`、`logout`、`me`；Argon2id、HS256 严格 issuer/audience/有效期、15 分钟访问令牌及 7 天可撤销会话。
- 刷新令牌只保存 SHA-256 摘要，原子轮换；复用和并发复用会提交会话撤销，再返回拒绝结果。
- TTL 只负责清理；授权显式检查会话有效期、撤销、用户状态及数据库中的最新权限。
- MongoDB 账号/IP 双层限流，切换用户名不能绕过同 IP 上限；账户错误不暴露是否存在。
- 新增实际失败测试：认证模型未就绪时原先仍返回就绪 200，修正后 503；更换用户名原先绕过 IP 限流，修正后 429。
- 全部 Rust 测试 21/21，Node 2/2；Clippy 在 CARGO_INCREMENTAL=0 环境下通过（绕过本机缓存硬链接告警，未修改项目编译策略）。
- 真实网络验证：登录/个人信息/刷新 200，注销 204，注销后访问和刷新 401。验证输出未包含密码或令牌；服务验证进程随后停止。
- Ruling: Task 3 的原生桌面登录/注销验收放在 Task 5，因为界面尚未构建；当前只记录 API verified，不把它冒充原生验收。若客户端适配发现问题，在 Task 5 修正后补齐证据。

## Task 6：系统参数（2026-10-25）

- 新参数 API 与页面，支持 string/number/boolean/json、分组、描述、版本更新、软删除和共享配置权限；省略值保持原值，显式 null 只对 JSON 类型有效。
- 参数值以有界 JSON 文本持久化，返回时恢复 JSON 类型；避免 `$oid` 等普通 JSON 键被当作 BSON 扩展类型。限制 16 KiB、16 层嵌套，审计不保存参数值。
- 修正两个实际失败：后端原先接受桌面不能准确往返的大整数；前端 JSON 溢出数字原先会序列化成 null。现在嵌套数字也检查有限数值及安全范围，大整数需用字符串表达。
- 9 项参数测试、Rust workspace 55 项、工具 2 项、客户端 17 项、页面 6 项通过；Clippy、Vue 类型检查和生产构建通过。页面验证非法 JSON/数值溢出提示、对象保存、显式 null 编辑、删除及先前模块回归。
- 参数查询性能基线：2000 条记录，默认排序与标识前缀查询均返回 20 条，扫描 20 documents / 20 keys。
- Ruling: 本机网络测试在受限沙箱中统一返回连接错误，使用已授权的正常本机网络权限重跑后通过；未修改请求实现或绕过功能验证。

## Task 6：指定角色范围核心（2026-10-25）

- 新 all/self/roles 范围聚合，角色显式记录 dataScopeRoleIds，返回可读角色标签；用户列表在分页前过滤，读取、修改、创建和角色变更均校验范围。
- 权限与范围同时按子集委派，角色分配还校验成员资格；修正“保留范围内角色、再附加范围外角色”原先可成功的绕过。被数据范围引用的角色不可删除，引用创建与删除的并发竞争通过事务保护。
- 新 `/roles/assignable` 仅需 roles.assign，分页返回最小可分配选项；用户选择角色无需授予全局 roles.read。选择器按标识远程搜索，超过首屏的角色仍可找到，当前选择展示名称。
- 本项目自己的 RBAC schema v1→v2 显式迁移新字段；新认证摘要和客户端严格使用新契约，无旧接口或摘要回退。
- 10 项范围测试通过；当前 Rust workspace 65 项、工具 2 项、客户端 18 项、页面 7 项全部通过，Clippy、Vue 类型检查和生产构建通过。页面验证指定角色编辑、范围内创建成员、范围缩减后原会话的下一次查询立即收缩。
- 实际查询基线：2000 条角色，列表和范围引用查询均返回 20 条、扫描 20 documents / 20 keys；缺索引时的失败记录显示扫描 2001 条。
- 原 vue-admin 的已知工作区状态未变。本阶段先细化 [客户设计](design-customer-scope.md) 并完成范围核心，客户 API/页面随后在下一节补齐；范围核心测试没有冒充业务资源验收。

## Task 6：客户归属与数据范围（2026-10-25）

- 新客户 API 与页面，活动编号忽略大小写唯一；支持联系资料、状态、归属转移、版本更新与软删除。内部搜索键不暴露，审计不记录联系资料和备注。
- all/self/roles 范围在服务端执行，角色和归属账号的成员资格变化对同一会话的下一次请求立即生效；范围外读取、编辑、删除返回 404，向范围外转移返回 403。
- 新最小归属人选择接口仅需 customers.write，不需要 users.read；远程搜索启用且可管理的账号，当前归属显示名称。
- 用户有未删除客户时阻止删除；客户创建、转移和用户删除在同一事务锁下维护归属不变量，包含并发竞争验证。归档客户仍保留归属约束。
- 实际失败修正：显式保留原归属人时不再把已停用账号误判为新归属；只有真正更换归属才要求新账号启用。
- 12 项客户测试通过，Rust workspace 77 项、工具 2 项、客户端 18 项、完整页面 8 项通过；Clippy、Vue 类型检查及生产构建通过。界面已验证 Owner/Operator/Viewer 的创建、编辑、只读限制、转移后可见性收缩和账号删除保护。
- 2000 条客户基线：all/self 分页返回 20 条时扫描 20 documents / 20 keys；真实 roles 范围 API 返回 20 条、统计 1000 条可见记录，本机完整回归实测约 249 ms。
- 客户模块完成不代表 Task 6 或完整目标完成；版本、登录/操作/错误日志、配置中心及 Task 7–12 继续推进。
