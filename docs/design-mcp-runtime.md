# MCP 运行核心

这是 Task 9 B 的进程、传输与 RPC 基础，属于已经批准的扩展/MCP 设计。固定使用官方 rmcp 3.5.1，新协议为 2026-07-28，客户端显式 Discover，不使用默认旧握手或 Auto 回退。主后台的持久连接管理、配置授权、业务工具与管理界面分别按子计划验收。

公共 RPC 已拆分到 `session`，进程所有权仍由 `process` 管理；HTTP 运行基础另见 [HTTP MCP 客户端设计](design-mcp-http.md)。该拆分更新本项目调用点，不保留旧命名空间的转发层。主后台 HTTP 配置引用和持久生命周期继续按后续接入，不能只凭核心测试勾选整个模块。

`Process::spawn` 只供受信任的宿主调用方使用。程序和工作目录必须为存在的绝对路径，参数、环境与运行限制都有预算；清空继承环境后只传入 ProgramSpec 的显式映射，不通过 shell 拼接命令。部署能力、用户身份和操作权限由主 API 在更高一层解析，不能把 HTTP 输入直接转换为 ProgramSpec。工作目录不是操作系统沙箱，批准的程序本身由部署者信任。

Windows 使用隐藏窗口、Job Object 和 KillOnDrop，Unix 使用独立进程组。监督任务持续持有原进程包装器，停止时终止其进程树并等待退出；停止等待超时返回“退出未确认”，监督仍继续，不假报已停止。Linux 使用 WNOWAIT 观察父进程，终止组之前不回收组长 PID，随后等待进程组消失；仅等待父进程不足以确认孙进程已退出。启动前返回的 Process 保留 PID、状态订阅和停止能力，协议发现失败后也保留可查询的所有权。协议发现成功才发布 Running；停止、崩溃和所有权释放均由真实子进程测试覆盖。

STDIO 使用自有有界帧适配器，将协议处理交给 SDK。默认最大帧为 512 KiB，增量读取保留未完成字节，拒绝超长或无效 JSON；并发发送期间也不能丢弃半帧。写入先序列化并检查大小再加换行。stderr 单独捕获、持续排空，默认最多保存前 64 KiB，并记录截断标记，不继承到主服务日志。包、脚本、工具响应和 stderr 均作为不可信数据处理。

Windows 的网络提供程序需要 SystemRoot 系统路径。测试程序及其孙进程通过显式环境映射提供该路径，未继承 USERPROFILE、HOME 或主服务 JWT 密钥。主 API 的部署能力解析也应明确列出所需系统环境，不复制整份环境。

客户端禁用响应缓存及过期回退。工具发现最多 16 页、128 个名称，拒绝重复名称、游标循环和超过预算的清单。调用参数为有界 JSON 对象，默认最多 64 KiB；并发槽位默认 4 个，满时发送前拒绝，不建立无界等待队列。工具名称是协议中的不透明值，不作为文件路径或 shell 片段使用。

每次调用只发送一个工具请求。complete、input_required 和 task 分别作为结果返回，不自动驱动多轮输入或重新执行操作。中途取消、超时、连接中断分别保留“远端效果未确认”的语义；调用 Future 被中断时，清理任务发送取消并持有原并发槽位，清理无法确认时终止连接。远端 JSON-RPC 错误只映射安全错误码，不把 SDK 的原始错误文本写入日志或返回给调用方。

实际测试夹具执行计数器操作、产生中间请求、分片响应、制造协议/超时/崩溃故障，并生成持续持有本地监听器的真实孙进程。测试检查效果不重复、取消通知、环境隔离、stderr 限制和进程树退出。这些是受控本机协议与进程验证，不能计作实际外部 MCP 上游或后台业务工具验收。

后续主 API 必须实现当前 JWT/PAT、角色和 Scope、all/self/roles 范围、批准能力 ID、进程运行实例、请求 UUID、持久结果与原子审计。网络上游沿用现有 DNS/TLS/代理/重定向限制和加密凭据引用；SDK 日志目标需要抑制原始通知/错误正文，调用记录只存安全摘要和受权限控制的结果。主服务重启后不能凭旧 PID 假报运行或任意终止进程，也不能因响应丢失盲目再次执行。

Windows 与 Linux 的 10 项真实进程测试分别通过。Linux 首次测试实际发现父进程退出后孙进程监听仍短暂存活，修复后原断言通过，没有增加测试延迟或放宽条件。`tools/test-mcp-linux.ps1` 使用固定摘要的官方 Rust 1.94.0 镜像，只读挂载源码及锁文件，不挂载 `.env`、主库数据或密钥，构建和严格 Clippy 在临时容器内完成后自动清理。此结果只证明运行核心，不代表整个主 API 或外部 MCP 上游已在 Linux 验收。整个 Task 9 B 与原重构目标仍保持进行中。
