# 配置版本与发版包

Task 6 的版本管理保存配置快照，支持创建发版、查询、查看、下载、导入预览和应用；功能调研确认菜单、API 元数据和字典是发版包的核心内容。新实现使用 Rust/MongoDB 模型和独立包格式，Tauri 安装更新沿 Task 12 实施。

## 资源与边界

- 版本记录为不可变配置快照：name、code、description、checksum、资源数量、创建者、时间、version 与软删除。code 使用有界安全标识，整个历史中唯一；不重用已删除发版的编号。历史快照不能被静默覆盖。
- `/api/v1/versions` GET/POST 捕获所选当前配置；`/{id}` GET 元数据与摘要、DELETE 带 version；`/{id}/download` GET 新 JSON 发版包。
- 捕获内容包含所选菜单及必要父级、字典与全部活动明细、系统参数、接口依赖；不包含管理员账号、角色授权、业务记录、令牌、密钥或运行日志。
- 版本列表只返回元数据与数量，避免读取大型包内容。包体上限 8 MiB，明确拒绝超限，不截断。下载文件名由安全版本编号生成，并附可校验 SHA-256。
- 元数据与不可变包体分别存放在 versions/version_packages；两者与成功审计在同一事务提交，包体写入失败不得留下孤立元数据。捕获使用 snapshot 读关注，源集合并发变化时仍取得同一一致视图。
- versions.read/write 管理版本记录；捕获、下载和预览包体还要求相应资源读取权限，应用还要求各资源写权限。不能经版本下载绕过参数等资源的读取权限。

## 新包格式

`format="tri-admin/config-bundle"`、`schemaVersion=1`，包含 release 元数据、resources 与 requiredApis。包内引用使用新领域的稳定键：菜单 path/parentPath、字典 key/明细 value、参数 key、接口 operationId。

- 菜单保持新 viewKey 注册表、权限操作码、路径唯一、无环及 16 层限制；捕获自动包含必要祖先，并在预览中列明。
- 字典包含新 label/value/sort/enabled 明细；参数保持新 valueType/value 边界，不隐式转换。
- 接口依赖用于核验目标服务已提供对应的 Rust API（operationId/method/path/requiredPermissions），不从 JSON 安装可执行接口。未知接口、权限码或不匹配的依赖会明确拒绝。
- 只接受这一新格式和支持的 schemaVersion，字段白名单验证；不解析旧 Go/Gorm 发版包或提供字段转换分支。

## 导入流程

1. 上传新包并预览：验证结构、大小、唯一键、引用、权限及目标数据，给出新增/更新/保持数量和有界差异详情；预览不修改配置。
2. 预览绑定操作者、包校验和、目标资源版本和过期时间。默认 createOnly；显式 merge 可创建或更新相同稳定键的资源，保留目标中其他资源，不隐式删除未列入的内容。
3. 应用必须引用有效预览。目标数据已变化时返回 409，要求重新预览；相同预览重复应用返回原结果，不重复更新版本或审计。
4. 菜单、字典/明细、参数、导入版本记录、预览结果和审计在同一 MongoDB 事务提交。复用各领域的校验规则，保持事务锁顺序；不能调用会自行开启独立事务的公开 CRUD 来伪造原子导入。
5. 只记录动作、目标、数量与校验和，审计不保存参数值或整个包。

## 先行依赖和验收

- 先补齐 `/api-catalog`：由新服务维护实际接口清单，包含 operationId、method、path、requiredPermissions 和分组。以逐接口缺权限及最小权限矩阵验证清单与真实路由/鉴权一致；API/权限目录页面展示两类元数据。
- API 清单就绪后实现版本服务与页面；导入事务需抽出可复用的领域校验/事务写入入口，禁止复制约束后逐渐产生两套行为。
- 测试捕获一致性、跨环境新 ID 分配、父子引用、未知格式/权限/接口、缺权限、重复键、并发改动、失败回滚、预览过期与重放、校验和、软删除和分页排序。
- 完成真实页面的创建、下载、预览、确认应用及拒绝流程。Windows 保存/打开对话框和安装包内的文件验证接入 Task 7/12，不以浏览器下载结果替代原生证据。

当前已实现后端捕获、元数据分页/读取、软删除和下载，包含资源读取权限、不可变性及校验和验证。页面、导入预览、事务应用与重放验收继续实施；目前不能标记完整版本功能完成，也未提前添加未实现页面的默认菜单。
