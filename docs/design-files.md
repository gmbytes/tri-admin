# 文件管理与数据工具

本设计细化全新实现计划 Task 7，不改变分类、分片上传、授权下载、本地/S3、CSV/XLSX、桌面文件对话框及失败恢复的完整范围。当前实现阶段以实施记录为准，设计不等于交付。

## 内容与文档分离

MongoDB 保存分类、文件、上传会话、分片清单和清理任务；内容保存在配置中心已启用的本地或 S3 配置中。文件绑定创建时的存储配置，切换默认存储不搬动既有内容；被文件、未结束上传或待清理内容引用的配置不能删除。凭据只在服务内部解密，不发给客户端。

采用不可变内容标识，而不使用用户文件名拼接存储路径。单对象上限 5 GiB，服务端接收流以 64 KiB 缓冲校验精确长度和 SHA-256，临时内容在受控存储根下。用户文件名只是受验证的显示元数据，下载固定附件与 nosniff，不将上传内容作为同源页面执行。

本地通过目录能力句柄访问受控子目录，校验完成后以同卷硬链接原子发布，目标已存在时不覆盖；不支持此原语的卷明确失败。S3 通过已保存的端点、桶、区域、前缀、寻址方式和凭据签名，PUT 使用 If-None-Match 条件创建；重试先验证已有内容，不能把不同内容覆盖成成功。传输保留 DNS/IP、TLS、不跟随重定向和不使用环境代理的边界。

S3 内容写入要求服务实际支持原子条件创建。在每个存储实例第一次写入前，使用独立 `_tri-probes` 标识执行小型写入、冲突写入、读取核验和精确删除；能力未通过则不发布用户内容，不提供忽略条件头的降级写入。连接中心的 bucket HEAD 仍然只表示连接/认证范围，不自动代表内容驱动可用。探测在写入前持久登记阶段和租约，进程中断后由有界维护确认，不遗失专用标识。

实施裁定：当前阶段采用服务端流式校验后写入的统一接口；直接预签名上传可减少服务器带宽，但需要另行完成存储回调校验，并为本地存储维护不同契约，暂不作为基础上传协议。这是实现取舍，未改变完整文件功能范围。

内容读取按预期长度和 SHA-256 流式验证，截断、超量或损坏产生明确错误。删除只针对一个已验证内容标识，幂等重试，不递归删除用户目录或桶前缀。取消发生在远程写请求发出后时，结果可能未知，必须交由持久上传状态和清理任务查询/恢复，不能立即宣称内容不存在。进程崩溃留下的暂存文件同样由受控恢复流程处理。

## 上传与授权

- 新 REST 资源使用 `/file-categories`、`/files`、`/uploads`，沿用 files.read/files.write；所有内容下载经过鉴权，不暴露永久公共 URL。
- 分类为全局配置，文件按所有者应用 all/self/roles 数据范围；指定角色使用所有者的当前角色关系，在分页前过滤，不能靠旧角色快照授予访问。
- 上传由 requestId 与操作者绑定，同键同参数返回原会话，异参冲突。服务端固定分片大小，分片索引、大小和摘要受校验；重复同片不重复接受，异内容冲突。
- 会话持久保存接收、校验、完成、取消和失败/待恢复结果。完成时只发布校验通过的内容；文件元数据与成功审计事务提交，存储副作用通过持久尝试记录和精确清理补偿，不假装文件系统与 MongoDB 属于同一事务。
- 取消不再接受新片；重启后通过会话和尝试记录继续确认或清理。分类/配置引用和并发删除共享固定锁顺序，避免出现失去定位信息的内容。

## 上传接收阶段

分类为全局受权限控制的配置；未发布上传会话固定归创建者，包含列表/详情、UUID 请求重放、分片接收和幂等取消。已发布文件单独按所有者当前 all/self/roles 范围授权，指定角色在分页前查询当前所有者关系。默认存储在首次创建时确定，精确重放不会因默认设置改变而重定向。

分片候选在本地 I/O 前登记，唯一接收清单、计数与审计同事务；失败或竞争产生的独立候选转入持久清理任务。取消先提交状态，清理按确定内容 ID 每批最多 100 个，并保留失败重试。过期 writing 原始片由独立恢复令牌接管，旧写入者不能再确认接收；正确内容可恢复清单与计数，缺失内容保留未知候选并释放接收容量。

## 发布与文件资源

完成请求先校验清单并持久排队，两个发布工作线程独立于接收容量执行。候选在 I/O 前登记，使用可续租的令牌隔离旧工作线程；整体 SHA-256 验证后才写入捕获的存储。文件元数据、上传完成结果和成功审计同事务，已完成请求重放只返回既有结果，不能再次发布已删除文件。

内容已保存但元数据提交失败时保留 stored/unknown 状态；上游 5xx 或取消后结果不明也保留候选。恢复先查询并验证已有内容，不能把缺少即时响应当作写入失败。主服务周期处理排队/过期发布租约，另用一个清理槽处理到期待清理任务；原始片与最终内容按已知类型分派存储，未知类型不假报已清理。

丢失或损坏的分片会失效，计数与清单同步减少；原摘要保持约束，重传使用新候选定位。发布前和提交前再次检查创建者当前写入权限。文件资料仅允许版本化修改名称/分类，删除后授权下载立即不可用，物理清理由持久任务收敛。

下载响应采用附件、nosniff 和 private/no-store，SHA-256 ETag 与长度供客户端核验。服务端保留最后一帧直到全流校验通过；头部发送后的流错误独立写入脱敏日志，不能把响应头的 200 当作内容已经完整送达。

分类删除与上传创建共享 files 锁；存储禁用/删除在 settings 后取得 files 锁，并检查活动文件、未结束上传、未清理候选和待清理任务，防止丢失内容定位。凭据轮换与无关服务设置不会因此被额外阻断。

## 有界维护与显式重试

原始片恢复每批最多 32 个，先在事务内取得恢复令牌，I/O 在事务外执行，最后在 rbac、files 固定锁顺序下重新核对当前权限与清单。只有有效内容和可接受的位置才补收一次；已有新候选时，迟到旧内容只进入精确清理，不替换现有指针。清理还检查活动文件和接收清单引用，不能删除仍在使用的内容。

暂存使用独立 `.lease` 文件持有跨进程文件锁，避免锁定将被硬链接发布的数据 inode。维护仅扫描 `.tri-staging` 内规范 UUID 的 `.tmp/.lease`，每轮最多扫描 1000 项、清理 100 项；超过一小时并且可独占取得租约才清理。活跃来源即使超过时限仍受保护，进程死亡由操作系统释放锁；新鲜文件、非规范名称和链接保留。文件锁采用 Rust 标准库的 [File::try_lock](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)。

S3 探测每轮最多处理 4 个日志。过期租约先隔离前台下一次写入；一旦所有写请求有确定结果，可精确删除。写入结果未知且 GET 仍缺失时保留；第二次冲突写入结果未知而只看到第一次字节时也保留，防止删除后使迟到写入重新成功。未结束日志继续保护存储配置，缺少凭据或网络失败只推迟维护。

发布未知时 complete 只要求再次查询。创建者显式调用 retry 后，正确旧内容仍直接完成；缺失或损坏时才在事务内登记全新候选，替换当前指针并审计。旧缺失候选保持 orphanUnknown，观察到迟到内容后清理；已观察到的损坏候选可直接退役。当前文件、完成结果和审计仍只发布一次，删除后重放不恢复文件。

## 数据工具与桌面

导入导出使用明确资源、字段映射、受控筛选和新模板；提供 CSV/XLSX，限制行数、文件大小、单元格和嵌套值。禁止执行 SQL 或任意表达式，导出对公式注入按单元格类型处理。导入先预览验证与授权，再按可重放批次应用，报告逐行错误及部分完成状态。

桌面使用原生打开/保存对话框与流式文件传输；浏览器预览提供受限文件选择。Windows 安装包内另验大文件、取消、断网、退出/重启及恢复，不用无头页面结果代替原生验收。

### 客户端传输基础

二进制分片使用不可变 Blob、固定 4 MiB 上限及摘要头，经与 JSON 请求相同的刷新锁重放。只有 UNAUTHENTICATED 触发一次共享刷新；刷新身份与既有账号不一致时撤销返回凭据并结束会话，不把原写入重放到另一个账号。API 请求拒绝重定向，令牌仍只在现有会话组件内存与授权的系统凭据库中处理。

每个客户端会话代际持有取消控制器，切换账号/服务和退出会立即中止旧请求；单次操作还可单独取消。下载读取响应流，校对捕获的长度、SHA-256 ETag、附件与媒体类型，每次向目标写入最多 64 KiB，空闲上限 30 秒、总传输上限 30 分钟。目标只有在长度和完整摘要通过后才提交；中断、损坏和拒绝会调用幂等清理。异步操作使用不可变元数据快照。

FileSink 是客户端写入目标契约，提供 write/complete/abort，把同一鉴权传输接到原生临时磁盘文件。浏览器目标将数据保留到校验通过才返回 Blob，选择/缓存上限明确为 128 MiB，超限在分配整份源文件前拒绝。通用传输不限制为浏览器缓存上限；原生磁盘核心已有独立 5 GiB 证据，文件页面、实际对话框和安装包内完整流程仍须单独验收，不能由浏览器 Blob 结果代替。

原生层只向前端返回短期句柄和公开元数据：在 Rust 内处理用户选择的路径、流式完整摘要、最多一个分片的读取和临时目标写入。续传记录限定服务器与账号，只保留创建请求及上传元数据；文件字节、令牌和本地绝对路径不进入 WebStorage。打开/保存命令使用 [Tauri 原生对话框接口](https://v2.tauri.app/plugin/dialog/)，实际界面操作仍遵守用户停止电脑自动操作的决定。

### 原生文件核心与 IPC

源文件通过已选择路径打开后保留文件句柄，以 64 KiB 缓冲计算完整摘要；分片读取最多 4 MiB，并在摘要前后及每片读取时核对长度和修改时间。服务器最终仍校验完整摘要，不能只依靠本地修改时间证明文件内容未变。普通文件、5 GiB 上限、分片位置与取消均在 Rust 核心验证，公开元数据不含本地路径。

最多保留 32 个短期操作。先预留句柄再打开选择器或计算摘要，耗时工作不占全局句柄表锁；取消和会话切换会撤销预留/活动句柄。迟到的选择结果不能重新安装源文件或提交目标。取消和最终发布共享提交门，按原生接受取消与提交的先后确定结果；已发布文件不会被后续取消删除。

下载在用户选择目录的能力句柄下创建独立 UUID 暂存文件，逐块累计长度和 SHA-256，校验、flush/sync 后才发布。新建模式用同卷硬链接拒绝覆盖，替换模式在保存选择器授权后原子重命名；失败和取消只清理本次暂存，原有目标保留。普通清理采用精确名称，失败返回待清理标识；进程异常终止后的持久恢复清理仍是桌面失败恢复的后续验收，不能由 Drop 的尽力清理代替。

前端接收网络流时仍以最多 64 KiB 交给目标，原生适配器合并成最多 1 MiB 的有序原始字节 IPC，Rust 再拆为 64 KiB 写入；尾部在完成前冲刷，取消丢弃未发送缓冲。源分片用 Tauri 原始 ArrayBuffer 响应，避免 JSON 字节数组；摘要进度事件最多约每 100 ms 一次。原生接口接收句柄与元数据，不接收前端任意路径，也不向原生磁盘命令传递服务器访问令牌。

Windows 的无窗口 IPC 集成测试独立声明 Common Controls v6 清单；实际应用仍使用 Tauri 默认清单。该声明满足 [TaskDialogIndirect 对 Comctl32 v6 的要求](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-taskdialogindirect)，避免测试程序在入口前错误加载 5.82；无需更改系统 DLL。开发配置只优化当前锁定 SHA-256 压缩依赖，5 GiB 磁盘门禁仍执行完整源摘要、分片传送、目标保存和重新读取校验。

## 文件工作区与续传记录

文件页面提供文件、上传与续传、分类管理三个标签页。文件列表沿用服务器当前 all/self/roles 授权；上传列表固定为当前账号，分类属于全局配置。修改文件名称/分类和分类资料使用 version，删除前明确确认；只读账号保留查询与授权下载，写入控件隐藏。分类和存储选择器按标识远程搜索，并单独保留已选 ID，避免首屏之外的绑定在编辑时被清空。普通上传可以使用服务默认存储，不要求 settings.read。

本机续传记录使用新 schemaVersion=1，以规范服务器地址和账号 ID 隔离，最多 32 条。首次 POST 前保存稳定 requestId 和不可变创建条件，收到并校验结果后绑定上传 ID，再开始传片。选择默认存储时持续保留原始省略条件；重放不会把后来改变的默认配置写回原请求。记录只包含文件名、大小、摘要、类型、分类/存储选择和操作标记，不保存字节、令牌、本地路径或原生句柄；字段损坏、跨作用域和存储失败会明确拒绝新建/续传。

重新选择源文件必须匹配整份长度和 SHA-256，文件名可以不同；已接受的分片从服务器清单核对后跳过。分片确认丢失时先 GET 查询，已接受便继续，尚未接受则保留任务供用户再次操作。暂停和离开页面中止等待及网络请求，并关闭源文件；即使底层读取尚未返回，也不能阻塞界面暂停或把迟到结果发到新会话。

完成、取消、核对、清理和显式重试在发送前标记本机待确认操作，每次标记使用独立 actionId。只有对应响应才能清除该标记，旧响应不能覆盖较新操作；查询得到明确状态后收敛对应待确认结果。未知发布只查询，不自动重复显式重试。来源变化导致整份摘要失败时提示取消后新建，不能把已接受的不同内容当作可覆盖片段。

移除本机记录与服务器取消/删除分开操作，界面说明其作用。已知服务器任务在本机记录不可用时仍能查询或取消。页面只显示当前标签页，上传后台核对仍可继续；全量页面验收包含丢失创建响应后刷新恢复、错误文件拒绝、丢失片段/发布响应的确认以及只读范围。

## 实施顺序与门禁

1. 内容存储引擎：先观察缺失模块的测试失败，再验证本地流式校验/原子发布/并发重试/取消/路径边界，以及隔离真实 S3 的写读删除、错误凭据和条件创建。
2. 分类与持久上传 API：先测试权限/数据范围、分片重放、竞争、取消、崩溃恢复、补偿和引用保护，再实现，保持成功审计原子性。
3. 文件页面与原生 I/O：真实页面上传、查询、分类、下载、删除与恢复，原生门禁单独记录。
4. CSV/XLSX 模板、预览、批次导入/导出和界面：验证实际新资源读写、类型、公式注入、越权与部分失败。

内容引擎自身只处理字节；HTTP 层已接入分类、上传接收/发布、文件授权和有界恢复维护。文件界面与数据工具继续实现；诊断探测和协议夹具不代替 Windows 安装包的大文件验收。

依据：[cap-std 目录能力](https://docs.rs/cap-std/4.0.3/cap_std/fs/struct.Dir.html)、[reqwest 流式 Body](https://docs.rs/reqwest/0.13.5/reqwest/struct.Body.html)、[S3 条件写入](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)。
