# MCP 持久管理

沿用已经批准的 Task 9 B。先交付实际 STDIO 连接和调用管理，随后接 HTTP、后台业务工具、插件能力绑定及界面；不把本阶段当作整模块完成。

部署能力从受保护的 `TRI_MCP_PROGRAMS_FILE` 读取，格式版本为 1。每项包含 id、label、现有程序/工作目录、固定 arguments、显式 environment、allowedTools 和有界超时。HTTP 连接输入只引用能力 ID，不能指定路径、shell 参数或环境；配置变化使用指纹识别，旧绑定须显式重新确认。公开能力目录隐藏实际路径、环境及指纹原文，Config 调试输出也不包含它们。

连接归创建者，使用当前 all/self/roles 范围；mcp.read 读取，mcp.write 管理生命周期，mcp.invoke 调用工具。JWT/PAT、当前用户、角色、Scope 和范围在事务内重查。创建与调用带操作者/UUID 指纹及回执，修改带记录版本。进程状态单独观察，后台状态变化不凭空变成用户配置修改。

启动、停止和重启首先原子提交意图、实例预留和审计，再由有界宿主工作执行外部效果。重启先确认原实例退出，才启动新实例；同一 UUID 重放只返回原操作。实例使用服务/运行 UUID 和实际进程所有权，HTTP 不接受 PID。服务失联与租约过期变为 orphaned，不能凭旧 PID 假报运行、任意终止或自动再启动。遗留实例只能在明确的交互式运维确认后解除阻塞，未知调用效果仍保留未知。

工具发现只公开部署 allowedTools 与实际发现清单的交集；这些注解和包中的 allowed-tools 都不授予权限。调用前再核对当前权限、连接版本和实例，记录参数摘要，不保存参数正文。结果有大小上限并加密保存，只有原调用者在当前授权范围内可读取原结果；列表提供安全元数据。取消、超时、断线和进程停止后的效果不确定，不能自动重发。发送前忙碌或取消可以明确记录为未发送。

原始 SDK 日志与 stderr 不进入主服务日志或公开响应。进程监视、心跳、结果提交和清理必须有界，审计失败不能留下未经记录的新启动；外部效果后的数据库提交只重试状态提交，不重做外部效果。主服务关闭会停止自身注册的进程，租约维护不自动执行遗留调用。

测试使用隔离 MongoDB 和真实受控子进程，覆盖版本/范围/去重/并发、启动取消、停止/重启/崩溃、调用取消与未知结果、结果加密和审计回滚。部署格式及接口使用见 [MCP 程序说明](mcp-programs.md)。真实 HTTP/MCP 业务与管理界面仍按后续计划验收。
