# 日志中心

Task 6 新日志模型使用登录、操作、请求错误三类记录，提供筛选、分页和受控清理。原项目只用于确认功能范围；不沿用其请求/响应正文或自由格式内部错误持久化方式。

- `GET /api/v1/logs` 需要 audit.read，全局审计授权独立于用户资源的数据范围。kind=login/operation/error，默认 operation；可按精确动作、账号、操作者、关联号、结果、状态与时间范围筛选，时间及 ID 稳定排序，页大小上限 100。
- 登录记录成功、错误凭据以及字段/限流等阻断；操作记录沿用同一业务事务中的成功审计，也包含注销和刷新复用撤销等安全操作。错误记录覆盖失败 HTTP 响应和捕获的处理器 panic，记录静态错误码与摘要。
- 不保存请求/响应正文、查询字符串、访问/刷新凭证、密码、Cookie、User-Agent 或原始数据库/异常信息。路径只使用已注册路由模板；未知路径记为 `<unmatched>`，方法白名单外记 OTHER。IP 只使用连接端点，不信任转发头。
- X-Request-Id 只接受规范 UUID；其他输入重新生成，避免任意头值流入持久日志和响应。请求上下文在异步任务内隔离；业务审计保存事件 ID，响应状态/处理耗时仅按这些 ID 补充，不按外部关联号批量修改。
- 请求错误和响应测量记录为有界的尽力写入，失败不能替换原响应；未迁移日志 schema 时不会自动创建日志集合。业务成功审计继续与业务修改原子提交。
- `POST /logs/cleanup` 需要 audit.read 和 audit.delete。body 包含 UUID requestId、kind、RFC3339 before 和 limit（1–1000，默认1000）；只允许清理至少 24 小时以前的记录。事务按时间/ID 选定本批具体记录，再删除并写清理审计与结果；同键同参重放原结果，异参 409，其他操作者 404。返回删除数量与是否还有更早记录，不隐式清空整库。
- 清理结果长期保留；新清理审计受 24 小时边界保护。事件本身不提供任意编辑接口。独立日志 schema/索引纳入 readiness，schema v2 启用日志中心默认导航。

验收覆盖权限、类型/字段白名单、时间与稳定分页、登录阻断、请求关联号并发隔离、正文/参数/异常脱敏、日志写失败不改变响应、清理边界与原子回滚、幂等和并发、真实索引查询基线与页面流程。

## 页面与待确认清理

- 日志中心提供三类标签、精确筛选、时间范围、稳定分页和只含安全字段的详情；audit.read 查看全局记录，audit.delete 才显示清理控件。
- 清理对话框固定本次类别，明确截止时间、每批上限和界面不能恢复删除记录；不会自动连续清空所有历史。
- 提交前将请求 UUID、类别、截止时间和上限保存到本机 WebView 存储，按服务器/账号隔离。每个请求独立保存，不能用同一标识覆盖不同条件；不保存密码、令牌、正文或日志内容。
- 结果未确认时保留原条件，页面重载或重新登录后可继续同一请求；重试可能完成尚未执行的原批次，也可能返回已保存结果。只有验证响应属于该请求且数量在原上限内后才移除待确认标记。
- 存储不可用时不提交新的清理；损坏记录不会被静默丢弃。已完成结果需要用户明确选择新建下一批，不复用或自动更新幂等键执行额外删除。
- 新项目自身 logs schema v2 添加实际页面菜单，readiness 和记录中间件共用版本常量；显式迁移保留已定制或删除的菜单。

浏览器的丢响应/重载/重新登录恢复已有页面测试；Windows 安装包内退出、重启与本机存储故障的实际验证仍归 Task 12，不用浏览器证据替代。
