# tri-admin 产品规范

当前架构以全新实现计划 V3 为准。旧项目仅帮助确定功能范围，不提供接口或代码兼容要求。

| 领域 | 交付能力 |
| --- | --- |
| 工作台 | 服务状态、资源概览、最近活动、游戏服状态入口 |
| 认证 | 登录、刷新、注销、当前用户、会话撤销、限流 |
| 权限 | 用户、角色、操作码权限、菜单和按钮控制、数据范围、审计 |
| 常规管理 | 字典/明细、参数、API/权限目录、版本、客户示例 |
| 日志 | 登录、操作、应用错误，筛选、分页与受控清理 |
| 文件 | 分类、上传/分片/下载/删除、存储驱动和授权 |
| 数据工具 | 新资源模型的 CSV/XLSX 导入导出、模板、字段映射 |
| 外部访问 | API Token、开放应用、应用用户、Scope、限流、调用日志 |
| 开发工具 | Rust/MongoDB/Vue 代码生成、历史、预览和可构建输出 |
| 扩展 | Skills/插件管理、MCP 工具与进程生命周期、AI 上游、工作流任务/取消/导出 |
| 配置 | 服务配置、密钥脱敏、MongoDB 数据源、文件/对象存储、邮件与外部服务 |
| 游戏管理 | tok 适配、区服/玩家查询、可靠管理任务和审计 |
| 桌面 | Windows 安装、服务器设置、网络反馈、文件对话框、更新与重启 |

角色初始包含 Owner（受保护管理员），后续可配置 Operator/Viewer。全部资源使用字符串 ID 和标准 HTTP 状态；删除优先软删除或明确的业务删除规则。
