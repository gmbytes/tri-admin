# AI 上游与持久工作流

本设计细化 V3 Task 9 C/D，继续新 Rust/MongoDB/API/Vue。原项目仅核对功能目的：需求分析、Prompt 工作流、流式显示、会话历史、取消与 Markdown 导出；不复制旧代理地址、响应包装、会话模型或主机落盘方式。

已只读确认本地没有保存的 HTTP 上游。已向用户异步询问服务偏好，当前先按推荐方向实现首个标准 Responses 适配器；厂商协议隔离在运行核心内。工作流和权限由 Rust 管理，不将编排状态交给旧服务。模型名称由管理员配置的允许列表提供，不硬编码“最新模型”或自动产生付费请求。

## 运行合同

上游配置引用已有加密 HTTP 集成的 ID 和精确版本。HTTP 地址为完整 Responses 创建端点；派生读取/取消地址只在同源端点后添加安全响应 ID，不接受调用者 URL、头、路径模板或任意透传字段。沿用 DNS/TLS、私有 CA、禁代理/重定向/重试及限流边界，凭据保持写入式。

全局 AI 上游的维护需要当前 ai.write、settings.write 和全部数据范围；读取批准模型目录需要 ai.read，发起模型操作需要 ai.invoke。运行、会话和工作流属于原操作者，应用 all/self/roles 元数据范围；提示和原始结果仅原操作者在当前授权下读取。开放应用/用户身份不进入管理员 AI 身份，模型输出和工具注解不能授予权限。

创建意图、原 UUID、输入摘要、原操作者、批准的上游/模型版本、限额及审计先原子保存。提示、上下文和输出使用现有密钥环加密，不进入 URL、列表、日志或浏览器恢复记录。已接受任务使用明确的身份/范围证明；任何下游操作前重查当前用户、权限与批准绑定，不伪造会话或 JWT。

Responses 使用语义事件与 sequence_number。背景请求可以按响应 ID 和已持久化事件游标恢复读取；keepalive 的连接计数不作为恢复游标。官方取消仅适用于背景响应，断开 HTTP 流本身不能证明上游已取消。[流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)、[背景模式](https://developers.openai.com/api/docs/guides/background)。

首版支持文本/拒绝输出和同步 JSON、流式响应、已知响应读取及显式背景取消；不会自动执行函数、shell、浏览器或模型提出的 MCP 请求。任务后续若使用批准的 MCP 节点，必须通过原权限处理器和持久调用记录，不直接解释模型文本。

为支持按 ID 读取和恢复，背景请求显式启用上游 `store`；前台请求关闭该选项。上游仍会处理并可能保存提示和响应，因此启用批准模型前应在配置界面说明这一实际数据去向；Rust 自身的密文存储不能改变厂商的数据处理策略。

## 预算与状态

运行核心初始上限：单个事件 64 KiB、整个上游响应 4 MiB、4096 个事件、32 个输出部分、文本结果 1 MiB、结构深度 32/节点 4096；提示 64 KiB，系统指令 16 KiB。单次调用总期限最多 120 秒、空闲读取最多 30 秒，主服务最多 2 个上游执行槽。部署可进一步收紧，不允许普通请求扩大。

状态区分 pending、running、succeeded、failed、cancelled 和 unknown。只有经过完整协议校验的终态才结束为已收到结果；拒绝、输出不完整和业务分析失败单独显示。发送前取消可明确未发送；发送后的断线、超时、取消回包丢失及不明确提交保留未知，不自动再 POST 生成。序号、响应 ID、输出内容及租约代际同事务提交，迟到 worker 不能覆盖新代际。

背景响应 ID 已知且原批准绑定仍有效时，恢复只 GET 上游状态/事件；未知 ID 或绑定变化不换目标重做。取消意图先审计，再执行有界取消；取消成功与请求取消分开记录。凭据/密钥不可用时拒绝发布明文，结果保留期与密钥退出按后续发布合同验证。

## 需求分析、工作流与界面

需求分析接收需求、场景及约束，输出建议模块/字段/风险和待确认项。Prompt 工作流支持新 Rust/MongoDB/Vue 工程生成、功能完善和 MCP 使用指导，保存固定版本的步骤、依赖、提示及预期输出。模型提案不直接写入代码生成定义、文件或业务资源；用户确认后调用已有新接口。

会话历史保留当前选择、消息分支和固定运行结果引用；取消任务不删除历史。Markdown 导出是受授权的私有产物，返回大小和摘要，使用既有下载/保存边界，不接受主机任意目录。Tauri 原生 GUI 暂停期间使用无界面及浏览器文件验证，原生门禁保留。

界面提供上游/批准模型选择、分析和 Prompt 工作流、流式进度、原请求恢复、历史、取消及导出。浏览器只保存服务器/账号隔离的 UUID 元数据；提示、凭据与结果不写 WebStorage。慢响应、切页、服务器/账号变化和当前权限撤销不得显示旧私有内容。

## 验证边界

先验证协议核心、真实受控 HTTP/SSE、状态机与错误预算，再接入 MongoDB 事务、当前授权/配置引用、持久 worker 和界面。测试包含分片 UTF-8、事件顺序、重复/截断、keepalive 游标、拒绝/不完整、取消/超时、一次生成、断线后只读恢复、租约/重启、审计回滚和密文。

真实厂商上游验收与协议夹具分别记录。当前没有上游凭据，完成受控测试不计为已完成真实厂商调用；不以 echo 或只读元数据替代模型接入。此设计不缩减后续 tok、游戏任务、备份/恢复、原生安装和完整发布验收。
